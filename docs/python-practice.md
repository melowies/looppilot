# Python practice and timing

Number of Islands (#200, or its canonical legacy LeetCode URL) supports `Solution().numIslands(grid)`. Two curated samples load automatically. Sample provenance: [LeetCode's problem page](https://leetcode.com/problems/number-of-islands/description/). Custom inputs accept a JSON matrix of `"0"`/`"1"` strings or `{"grid": [...]}`; expected output is a JSON integer. The registry in `src/lib/python-problems.ts` explicitly defines supported problems. Other problems keep code storage and custom cases without claiming execution support.

Run Code snapshots the current **unsaved** editor content and cases. A fresh Pyodide 0.27.3 worker executes the Python `class Solution` method for each case; each gets a new namespace and parsed grid, so mutation does not affect later cases. `List`, `Optional`, `deque`, `defaultdict`, and `Counter` are available. The runtime is pinned in npm and copied into ignored `public/python/` during install/dev/build. No runtime CDN is used. See [Pyodide's worker documentation](https://pyodide.org/en/0.27.3/usage/webworker.html).

The worker belongs to a sandboxed iframe with an opaque origin, without same-origin permission, storage access, or the parent document. The trusted page fetches fixed runtime assets and transfers their bytes, source, and cases into the sandbox. Its inherited Content Security Policy denies network connections and external scripts. The Python JavaScript bridge therefore cannot access the application's origin or authenticated APIs. No Next.js API accepts or executes submitted Python. All workers are disposable; initialization has a 30-second bound, and the **entire sample suite** has a 5-second execution limit. Stop, timeout, engine failure, switching attempts, and unmount tear down the worker. Timeout is reported for the suite; results do not claim per-case completion when the suite was interrupted. Console and error output are bounded. This is local practice, not a secure grading service or a LeetCode judge.

Passed, Wrong Answer, Runtime Error, and Time Limit Exceeded describe sample execution only. They never set `correctness`, assistance, hints, readiness, or task completion. Results hold the expected outputs from the run's snapshot; edits mark them stale. Engine failures preserve code and custom cases; Run Code retries with a fresh worker.

The timer starts on code edits or Run Code, with explicit Pause/Resume. It uses monotonic elapsed milliseconds internally and exposes seconds (including fractional seconds) independently of render/interval counts. Hidden tabs pause immediately; inactivity pauses exactly five minutes after the last keyboard/pointer activity even if interval delivery was throttled. Returning to a tab does not resume passive viewing; editing or Resume does. Save pauses the clock and stores its snapshot; later editing can continue a measured attempt.

`duration_minutes` receives `ceil(active_seconds / 60)`. Exact seconds and `measured`/`manual` provenance live in the optional `timing` object of the existing `looppilot-workspace-v1` evidence envelope in `coding_attempts.test_results`. No database migration is necessary. Historical records without timing metadata keep their original minutes (including null); passive viewing and editing cannot infer historical timing. Use New attempt to measure fresh practice, or explicitly use the exceptional manual correction control. Untouched legacy free-text evidence remains unchanged when no cases or timing are added. Unknown duration is labeled unknown.

Account/problem-scoped local recovery stores the current code, reflection, cases, attempt selection, baseline, and timer checkpoint. Refresh, normal navigation, and closing pause and persist; reopening restores a paused clock, excluding time away. A once-per-second checkpoint limits data loss if the process crashes without lifecycle events. Browser storage failures show an actionable warning. This recovery stays on that browser, separate from the explicit authenticated database save. Measured active practice time is not a guaranteed measure of all reasoning time.

```powershell
node node_modules/@playwright/test/cli.js test --config playwright.crud.config.ts python-execution.spec.ts --workers 3
```

Browser tests execute the actual self-hosted WebAssembly Python runtime and Monaco clipboard/keyboard handling. Only Supabase authentication/persistence is intercepted by the existing isolated fixture; this does not verify hosted Supabase Auth or CRUD. Timer lifecycle tests use Playwright's browser clock plus visibility events, and unit tests use fake timers for exact arithmetic. Screenshots are saved under ignored `artifacts/`.
