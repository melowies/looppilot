# LoopPilot continuation guide

## Product and scope

Personal Amazon SDE I preparation MVP. English interface with a warm rose study-journal identity: cream paper surfaces, blush and berry accents, Averia Sans Libre headings, Karla body/interface text, and a Gochi Hand wordmark and occasional journal date annotation. Desktop top navigation and persistent mobile bottom navigation; no primary left sidebar. Use concise functional copy; do not reintroduce decorative uppercase eyebrow labels, numbered headings, generic motivational slogans, or placeholder flower logos. Preserve real user history. Never seed fictitious completed attempts, infer missing historical dates/durations, claim offer probabilities, or equate assisted/viewed solutions with independent passes. No paid resources or deployment without explicit permission. The adaptive planner has an explicitly authorized optional OpenAI coaching layer: off by default, server-only credentials, separate user consent, bounded/cached requests, validated choices, and deterministic fallback. Do not make live paid AI calls during development without permission. No speech, calendar synchronization, payments, or complex/scored mocks.

## Architecture

- Next.js App Router, React, strict TypeScript, Tailwind v4 plus global design tokens.
- `src/app/[[...view]]/page.tsx`: shared client workspace with actual navigation routes. No credentials means empty read-only setup preview. Supabase configured means email/password login gate.
- `src/app/coding/[problemId]/practice/page.tsx`: dedicated authenticated IDE workspace. Opening a library problem navigates here. `coding-practice.tsx` owns code/reflection drafts, existing-attempt selection, real Supabase insert/update, manual test cases, save failures, and unsaved-change warnings for links, Back, reload/close, attempt switching and sign-out. New records default to `unverified` with unknown duration. Saving never infers a pass or creates tasks. Existing historical fields and non-Python code remain editable; non-Python code uses plain-text Monaco mode, never relabelled as Python. There is no code-writing modal.
- `python-editor.tsx`: lazy, self-hosted Monaco Python editor with syntax highlighting, indentation, bracket closing/matching, folding, line numbers, themes, font size and Ctrl/Cmd+S. Ctrl+M toggles Tab focus navigation; Tab/Shift+Tab otherwise indent. `scripts/prepare-monaco.mjs` copies pinned-compatible Monaco 0.52.x AMD assets and license from npm into ignored `public/monaco/` at install/dev/build; do not use a CDN. Keep generated assets excluded from ESLint. Desktop separators support pointer capture and arrow-key resizing; mobile uses Problem/Code/Tests/Reflection tabs.
- `src/lib/coding-workspace.ts`: typed runner interfaces and backward-compatible test-case/timing serialization in existing `coding_attempts.test_results`. `python-problems.ts` curates #200 samples and the `Solution.numIslands` signature. `python-runner.ts` runs current unsaved Python in a disposable opaque-origin sandbox worker using self-hosted pinned Pyodide bytes, with network-denying CSP, initialization/execution timeouts, and cancellation. Never execute submitted Python on the Next.js server or couple sample passes to correctness/readiness. `practice-timer.ts` and `use-practice-timer.ts` measure active seconds, pause hidden/idle sessions, and restore paused local recovery. Save rounds minutes up and preserves exact seconds/provenance in the evidence envelope; historical durations without timing metadata stay untouched. No schema migration is required. See `docs/python-practice.md` for behavior and limitations.
- `src/components/workspace.tsx`: screens, CRUD handlers, authenticated browser lifecycle. Shared fields/badges/dialogs are in `ui.tsx`; auth, editor fields, and settings have separate components. `Field` uses explicit `aria-labelledby` so select options do not pollute accessible labels. Native dialogs portal to `document.body`; critical viewport geometry lives in `dialogViewportStyle` on the element: fixed at 50%/50% with translate(-50%,-50%), margin zero and viewport-constrained scrolling. Lookup controls use their own component-local two-column grid, with help text outside the controls row. Body/root scroll are locked and restored, Tab wraps, Escape closes, and opener focus is captured before child autofocus. Errors remain visible; save failures do not close editors. See `docs/dialog-positioning.md` for measured browser evidence and the distinction between a reproduced CSS failure and an unverified browser-cache explanation.

Apply only new migrations to existing databases; never edit an applied migration. UI checks canonical legacy URLs; database uniqueness covers concurrent numbered inserts. ## Decisions and conventions

Adaptive planner verification on 2026-10-18: lint, strict TypeScript, 97 unit/embedded-PostgreSQL tests, production build, all 42 authenticated Chromium checks (`--workers=3`), and four setup-preview checks passed. Nine new planner checks cover desktop/wide/mobile availability, completion/pin preservation, skip and cross-date rescheduling, real-evidence replanning, AI-unavailable fallback, and local-day rollover. Screenshots: `artifacts/{desktop,wide,mobile}-adaptive-plan.png`. Background planner state lives in a sibling host to prevent controlled Monaco edit races; problem creation waits for initial history loading before duplicate checks/dialog opening. Timer tests pause at a future clock instant to avoid a host/browser timestamp race. No IDE rewrite, remote migration, deployment, live Supabase verification, or paid/live OpenAI request was performed. Apply the new additive migration manually to enable remote persistence. No new dependencies were added.

- Dates are ISO date-only strings; study timezone defaults to Europe/Istanbul, configurable. Interview date is never assumed.
- Adaptive reviews D+1, D+3, D+7 from first attempt; only independent passes on later distinct eligible days advance one stage. Failure/assistance raises priority and delays a retry until the next day without advancing. A failure can reopen recovery after three successful reviews. Task completion alone never advances learning evidence. Up to five review candidates; all work competes within explicit time budgets with category diversity. The original `plan()` remains a compatibility fallback; the Study Plan uses the adaptive engine.
- Independent solve = self-reported correctness `passed`, assistance `independent`, hints zero. Duration can be null. Browser sample execution is separate evidence and never promotes a solve.
- Readiness needs 5 distinct problems, 3 patterns, 2 stories. Formula v1: 70% unique independently passed problem ratio + 30% ready story ratio. No fabricated historical scores; user explicitly saves current snapshots.
- Imports are atomic and append only new records; source IDs are file-local. Export the account, validate the account-aware preview, review conflicts/warnings, then import. Exact repeats are skipped and original imported origins survive user edits. Materially edited source files are not updates: review their preview for additional records.
- No automatic migrations against a remote database. Supply `.env.local`, apply migration manually, configure Supabase Email auth and redirect allowlist. Do not commit secrets.
- Verify lint, types, tests, and build after meaningful edits. Run browser checks for UI changes where possible. Live Supabase Auth requires real credentials and email confirmation; do not claim it passed without testing it.
